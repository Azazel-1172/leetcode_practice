## 題目

给定一个平衡括号字符串 `S`，按下述规则计算该字符串的分数：

- `()` 得 1 分。
- `AB` 得 `A + B` 分，其中 A 和 B 是平衡括号字符串。
- `(A)` 得 `2 * A` 分，其中 A 是平衡括号字符串。

 

**示例 1：**

```
**输入： **"()"
**输出： **1
```

**示例 2：**

```
**输入： **"(())"
**输出： **2
```

**示例 3：**

```
**输入： **"()()"
**输出： **2
```

**示例 4：**

```
**输入： **"(()(()))"
**输出： **6
```

 

**提示：**

1. `S` 是平衡括号字符串，且只含有 `(` 和 `)` 。
2. `2 <= S.length <= 50`

## 面試官問答

### 1. 直覺上可以用頭尾兩個指標往內縮，外層每包一圈就 ×2。為什麼這樣做行不通？

<details>
<summary>參考答案</summary>

頭尾指標隱含一個假設：`s[0]` 和 `s[n-1]` 是一對括號。但遇到 `AB` 的形狀就不成立，例如 `()()` 的 `s[0]` 是跟 `s[1]` 配對，不是跟最後一個字元。所以第一步就配錯了，後面的 ×2 邏輯也跟著錯。要先找出真正的配對位置（用 balance 歸零切區塊），或改用 stack 從內往外結算。

</details>

### 2. stack 解法裡每一格代表什麼？為什麼一開始要先放一個 `0`，拿掉會怎樣？

<details>
<summary>參考答案</summary>

每一格代表「某一層括號目前累積的分數」，最底下那格是最外層，也就是還沒被任何括號包住的那一層。遇到 `)` 時，會把這層算完的分數加到上一層。最外層的 `)` 結算時，上一層就是那個初始的 `0`。

拿掉的話，像 `()()` 第一個 `)` pop 完 stack 就空了。C++ 的 `st.back()` 在空 vector 上是未定義行為；JS 的 `stack[stack.length - 1]` 會變成 `stack[-1]`，`undefined + 1` 得到 `NaN`，最後 `stack[0]` 回傳 `undefined`。

</details>

### 3. `max(2 * v, 1)` 是用「`v == 0`」來判斷內部是不是空的。會不會有內部非空、但分數剛好是 0 的情況被誤判成 `()`？

<details>
<summary>參考答案</summary>

不會。任何非空的平衡括號字串分數至少是 1，可以用歸納法證明：`()` 是 1，`AB` 是 `A + B ≥ 2`，`(A)` 是 `2A ≥ 2`。所以 `v == 0` 若且唯若這層內部是空的，`max(2 * v, 1)` 剛好對應兩條規則：空的時候得 1，非空的時候得 `2 * v`。

</details>

### 4. stack 解法的時間、空間複雜度怎麼算？空間真的是 O(n) 嗎？

<details>
<summary>參考答案</summary>

時間 O(n)：每個 `(` 只 push 一次、最多 pop 一次，每個字元的處理都是 O(1)。

空間更精確的說法是 O(d)，d 是最大巢狀深度，stack 長度最多是 d + 1。`()()()` 這種全部並排的字串，stack 最多只有 2 格；`((...))` 這種全部巢狀的字串，深度是 n/2，這時才是 O(n)。

</details>

### 5. depth 解法只在「`)` 前一個字元是 `(`」的時候加分。其他 `)` 代表的 ×2 跑去哪了？

<details>
<summary>參考答案</summary>

分數規則只有加法和 ×2，乘法可以分配到加法上：`2 × (A + B) = 2A + 2B`。把整個式子展開之後，只剩下一堆 `1` 乘上不同次數的 2。`1` 只會來自 `()`，乘幾次 2 取決於外面包了幾層。所以外層 `)` 負責的 ×2 已經包含在每個內部 `()` 的 `2^depth` 裡，不需要另外處理。

例如 `(()(()))` = 2¹ + 2² = 6。

</details>

### 6. depth 解法用了 `s[i - 1]`，`i == 0` 時不會越界嗎？如果輸入可能不合法，要怎麼改？

<details>
<summary>參考答案</summary>

題目保證輸入是平衡的，所以 `s[0]` 一定是 `(`，會走 `depth++` 那個分支，不會在 `i == 0` 時讀 `s[-1]`。

如果輸入可能不合法，需要額外加兩個檢查：掃描過程中只要 `depth < 0`，就代表 `)` 太多；掃完之後 `depth != 0`，就代表 `(` 沒有關閉。另外改成記錄「前一個字元」的變數，而不是讀 `s[i - 1]`，就完全沒有越界的問題。

</details>

### 7. 答案最大可能是多少？C++ 用 `int`、JS 用 `1 << depth` 會不會出問題？

<details>
<summary>參考答案</summary>

長度 n 的最大分數是 2^(n/2 − 1)，用暴力列舉 n = 2 到 18 的所有字串驗證過。n = 50 時最大值是 2^24 = 16,777,216，`int` 放得下。

JS 的 `<<` 會先把數字轉成 32 位元有號整數，實測 `1 << 31` 是 `-2147483648`、`1 << 32` 是 `1`。所以 depth 到 31 就會出錯，只是這題 depth 最多是 24，碰不到。若 n 放寬到 10^5，要改用 `BigInt`，或者題目會要求取模；C++ 的 `long long` 也只能撐到 depth 62。

</details>

### 8. 變形題：如果規則改成 `(A)` 得 `3 * A` 分，兩種解法各要怎麼改？

<details>
<summary>參考答案</summary>

stack 解法只需要把 `max(2 * v, 1)` 改成 `v == 0 ? 1 : 3 * v`。

depth 解法也還能用，因為 ×3 一樣可以分配到加法上，每個 `()` 的貢獻改成 `3^depth`。但這時就不能用位移了，要另外維護一個 `pow` 變數：遇到 `(` 就乘以 3，遇到 `)` 就除以 3。

如果規則改成「`AB` 得 `A × B` 分」，分配律就不成立了，depth 解法不能用，只剩下 stack 解法可以照規則模擬。

</details>

### 9. 遞迴切區塊、stack、depth 三種寫法，各自的取捨是什麼？

<details>
<summary>參考答案</summary>

- **遞迴切區塊**：用 balance 歸零切出 `A`、`B`，再遞迴處理 `(A)` 的內部，最直接對應題目規則。缺點是每層遞迴都要重新掃內部，`((...))` 這種輸入最差是 O(n²)，而且遞迴深度 O(n)。
- **stack**：O(n) 時間、O(d) 空間，照著規則從內往外模擬，規則改了也容易調整。
- **depth**：O(n) 時間、O(1) 空間，但必須先看出分配律，規則一旦不滿足分配律就不能用。

面試時通常先講 stack 解法，被追問空間能不能優化，再拿出 depth 解法。

</details>

### 10. 時間複雜度還能比 O(n) 更快嗎？

<details>
<summary>參考答案</summary>

不能，下界是 Ω(n)。可以這樣構造：每個區塊是 `(()())`（4 分）或 `(())()`（3 分），兩種區塊只差在下標 3、4 的字元互換。把 k = n/6 個區塊串起來，答案是 `3k + (第一種區塊的數量)`。

如果演算法沒讀某個區塊下標 3、4 的字元，對手就可以把那個區塊換成另一種，其他讀過的字元都不變，但答案差了 1。所以每個區塊至少要讀一個字元，總共至少 n/6 次，現在的 O(n) 已經到頂了。

</details>

### 11. 空間還能再壓嗎？如果字串是一個字元一個字元串流進來呢？

<details>
<summary>參考答案</summary>

depth 解法的輔助空間已經是 O(1)，只有 `ans`、`depth`、`i` 幾個變數，輸入字串本身不算在內，所以不能再壓了。

串流的情況下 depth 解法也能直接用：只要把 `s[i - 1]` 改成一個 `prev` 變數記住上一個字元，讀一個字元處理一個，完全不用存整個字串。stack 解法則需要 O(d) 空間記錄每一層的分數。

C++ 版的參數是 `string s` 傳值，會複製一份輸入，但這是 LeetCode 固定的函式簽名，不算演算法本身的輔助空間。

</details>
